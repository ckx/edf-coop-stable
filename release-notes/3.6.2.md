# EDF6Coop 3.6.2 movement and aim fixes

This prerelease fixes two code paths found during the aim and jitter review. Live multiplayer improvement remains unverified, and the post-hit facing reversal still needs the 3.6.1 diagnostics, retained here.

- A moving copy that becomes stationary against a constraint can no longer sustain a growing braking estimate from corrections that did not move it. The regression's 60 m/s fictitious velocity now decays to zero, while existing tests for real braking still pass.
- Older or repeated paired aim records preserve the current pitch, yaw and aim accumulator. Other native state still processes. Aim freshness is independent of position freshness, so an intervening position-only record does not discard useful aim. Native records without the custom player block keep their original behavior.

Validation: MSVC on Windows and clang/MinGW under Wine each passed all 31 non-stress tests, including all 18 game-code cases without skips. DirectNet and LogFileCap stress tests were excluded. Tests cover the blocked-motion transition, recovery, real braking and reordered/native-only aim records.

Settings and netcode protocol are unchanged. Compatible peers can remain in the same room; each receiver benefits when it updates. For the next capture, update everyone and leave [Diagnostics] Player=1 enabled. Note the time and player if jitter or reversed facing occurs, then close the game and collect every player's log.

Extract the whole package and run INSTALL.bat on Windows or bash install.sh on Linux. Existing settings and other mods are preserved. Proton requires WINEDLLOVERRIDES="winmm=n,b" %command% in Steam launch options.
