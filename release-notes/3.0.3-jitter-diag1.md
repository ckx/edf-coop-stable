# EDF6Coop 3.0.3 player jitter diagnostic 1

This prerelease records player movement around large corrections to investigate
the jitter seen by hosts and joiners. It does not change the movement algorithm
or claim to fix the jitter. The wire format and netcode protocol remain compatible
with 3.0.3. The DLL's version banner still reads 3.0.3; identify this diagnostic by
the `PLAYER motion diagnostics ON` startup line.

Download `EDF6Coop-3.0.3-jitter-diag1-full.zip`. It includes the plugin, the fixed
EDFModLoader, Windows and Proton installers, licenses and translated instructions.
The `.sha256` file contains the package checksum. Stable 3.0.3 remains the latest
normal release.

## Install and capture

1. Close EDF6 and back up `Mods/Plugins/EDF6Coop.dll` if present.
2. Extract the full ZIP. On Windows, run `INSTALL.bat`. On Linux/Proton, run
   `bash install.sh`, optionally followed by the game folder path in quotes.
   Existing settings and other mods are preserved.
3. On Proton, use the Steam launch option
   `WINEDLLOVERRIDES="winmm=n,b" %command%`.
4. Install this diagnostic on the host and joiners collecting logs. Start fresh
   game processes and reproduce the jitter. Note the local clock time, who was
   moving, who saw the jitter, and whether the movement was running, jumping or
   boosting.
5. Close the game and collect each tester's `Mods/Plugins/EDF6Coop.log`, together
   with their host/joiner role and observations.

Movement logging is enabled by default. `[Diagnostics] Player=0` disables it.
A correction of at least 0.25 m, a warp, or a sample age of at least 200 ms triggers
a burst of up to eight preceding and sixteen current/following driven frames.
Each object can trigger once per 30 seconds; all objects share a limit of 96
`PLAYER motion` lines per 30 seconds. The `t` field is the original hook time in
milliseconds, including for buffered history printed later.

The traces record the received sample, physics and object positions, observed
movement, requested corrections and estimated local velocity. They distinguish
changes in incoming movement from the correction loop reacting to local physics.
They do not establish that a requested correction was actually applied.

Restore the backed-up DLL or reinstall stable 3.0.3 after testing.

## Validation

This package contains the clang/MinGW-w64 build tested under Wine. The native
Windows build host was unavailable; this diagnostic has not been validated with
MSVC or on native Windows. The DLL uses the Windows ABI and bundles its compiler
runtimes statically.

All 27 non-stress tests passed under Wine, including 15 tests against the supported
EDF.dll. A focused check of the production trace functions passed frame ordering,
burst length, cooldown, global line cap and window reset checks. Live multiplayer
behavior remains unverified.
