# EDF6Coop 3.6.3 on-foot aim update fix

This prerelease addresses the aim-update gap found in the October 28 session. The host kept receiving K1's position blocks while his paired native aim updates stopped, including while he was on foot.

On-foot players now include the game's native aim fields with every player-sync position block. Any delivered block can refresh aim, even when the receiver applies only every third written block. The game's vehicle and downed-player exclusions remain in place.

The shooter must update for other players to receive the additional aim. Update everyone for the next multiplayer check. Settings, the custom player-block format and netcode protocol 4 are unchanged, so compatible older versions can still share the room.

The regression uses the real EDF.dll mask, writer and reader and selects every third block in all three phases. Two phases leave aim stale before the fix; all refresh aim afterward. The exact production cause of record thinning and improvement to the reported live shot-direction desync remain unverified.

Validation: MSVC on Windows and clang/MinGW under Wine each passed all 31 non-stress tests, including all 18 game-code cases without skips. DirectNet and LogFileCap stress tests were excluded.

Leave [Diagnostics] Player=1 enabled. Repeat on-foot firing while another player watches, including after entering and leaving a vehicle. If shots point the wrong way, note the time, shooter and weapon, then collect everyone's logs after closing the game.

Extract the whole package and run INSTALL.bat on Windows or bash install.sh on Linux. Existing settings and other mods are preserved. Proton requires WINEDLLOVERRIDES="winmm=n,b" %command% in Steam launch options.
